# Review Integrity

## Core Principle
Honest review > impressive-looking review

## Rules
- NEVER invent issues to appear thorough
- NEVER inflate severity to seem rigorous
- Empty categories = don't include them
- "No issues found" is a valid report
- Uncertain? Say "possible concern" not "definite problem"

## Valid Report Outcomes
- "No Must Fix items found"
- "Code follows codebase patterns well"
- "Tests adequately cover the implementation"
- "Design decisions are sound for current scope"

## Before Flagging, Ask Yourself
- Is this a real problem or a style preference?
- Would a senior reviewer actually block on this?
- Am I sure, or am I guessing?

## Severity Honesty
- Must Fix: Would actually break or block the PR
- Should Discuss: Genuinely worth exploring, not nitpicking
- Consider: Only if actually worth the effort to change
